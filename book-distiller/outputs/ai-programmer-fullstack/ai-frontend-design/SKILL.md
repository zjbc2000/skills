# AI 前端设计与实现

## 何时使用
- 你有一个网站/应用界面想法，想零代码或低代码做出来。
- 你需要用 AI 生成前端组件（按钮、卡片、表单、导航栏），或把截图/设计复刻成网站。
- 你想用 Figma 做设计蓝图（框架/样式/网格），或让 AI 直接"视觉"而不是"语言"驱动。
- 你要判断该用"一体化平台"还是"专业工具"来起步。

## 核心规则

1. **先选对工具档位**：零基础、想最快出成果 → 用 Trickle（一体化平台，魔法画布+托管+轻量数据库一条龙）；要像素级、专业 UI → 用 v0.dev；要精确控制设计系统 → 用 Figma；要 AI 全程自主建房 → 用 TRAE SOLO。来源：第2章

2. **Trickle 用"可视化上下文工程"而非纯聊天**：魔法画布是无限延伸的智能白板，拖图片、写笔记、画草图，AI 实时观察布局关系与风格，把画布内容作为蓝图建出真实可交互、可发布的网站组件。别把想法只打进对话窗口。来源：第2章

3. **v0.dev 用"迭代对话"而非一次生成**：第一个提示词只是草图起点，把复杂目标拆成一系列简单、连续的指令，先出基础框架，再逐步加细节、调样式、改布局（如"加悬停变深""点击加缩放"）。像雕塑一样层层打磨。来源：第2章

4. **描述交互用行业术语**：v0.dev 能理解"汉堡菜单""响应式""悬停"这类术语，一句话即可实现现代网站必备功能，无需写媒体查询。描述状态变化（悬停/点击）时直接说行为+效果。来源：第2章

5. **"视觉"比"语言"信息损耗小**：说不清字号/间距/色值/阴影时，直接上传截图让 v0.dev 复刻。一张图包含成千上万个布局、色彩、排版数据点，胜过千言万语。来源：第2章

6. **Figma 坚持"框架优先、绝少用组"**：框架是"智能容器"（有约束、可裁剪、支撑 Auto Layout 和组件），组只是临时捆绑；UI 是能适应不同屏幕的灵活系统，不是静态图片。构建图标时先建 24×24 框架当"画板"，再画形状、布尔运算、扁平化、居中。来源：第2章

7. **用"设计令牌"建立视觉语言**：把重复出现的颜色/字体保存为语义化样式（color/primary、typography/h1），改一处全局同步；用布局网格（8pt 均匀网格/12列网格）强制对齐与间距一致。样式指南放到专门"基础规范"页面文档化。来源：第2章

8. **TRAE SOLO 是"自主代理"而非"助手"**：它坐上驾驶位独立完成需求分析→写 PRD→装环境→写代码→跑命令→预览→部署的全流程，你只需扮演产品经理提需求；一体化工作台（编辑器/终端/浏览器/文档）的"实时跟随"让 AI 工作透明可监督。来源：第2章

## 检查清单
- [ ] 是否按场景选对工具（快速验证→Trickle / 像素级→v0.dev / 设计系统→Figma / 全程自主→TRAE SOLO）？
- [ ] 生成前端是否走了"先基础框架、再迭代打磨"而非一次性下完整需求？
- [ ] 交互/响应式是否用行业术语一句话描述（汉堡菜单、悬停、点击缩放）？
- [ ] 说不清视觉细节时，是否用截图/视觉驱动而非硬用语言描述？
- [ ] Figma 是否用框架不用组、是否建立了颜色/文本样式与网格？
- [ ] 用 TRAE SOLO 时是否给了清晰的 PRD/需求，并借助"实时跟随"监督过程？

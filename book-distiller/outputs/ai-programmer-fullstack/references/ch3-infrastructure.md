# 第3章精要：基础设施搭建——节俭全栈工具箱

> 全章主旨：用零前期成本的工具组合搭起专业级应用，从部署、数据库、认证到存储、域名。

## 3.1 节俭全栈
- **餐厅运营模型**：前端=大堂、后端=厨房、数据库=仓库、API=服务员。选工具先想清楚它在"餐厅"里的角色。来源：3.1
- **三类工具划分**：核心基础设施（部署/数据库/认证/存储）、核心外围服务（完善功能的模块）、生产力与设计工具。来源：3.1
- **Vercel**：应用的"全球之家"，部署到边缘网络（极速响应/全球一致/自动容灾）。与 GitHub 集成白送 CI/CD（push→自动化流水线→构建测试→全球上架）。来源：3.1
- **免费额度战略**：起步阶段无须掌握所有工具，先以零成本验证想法，后期按需扩展。来源：3.1

## 3.2 域名——数字身份
- **域名 vs 托管**：托管=网站的"土地"（地基），域名=独一无二的"地址"（门牌号），两者缺一不可。来源：3.2
- **DNS 是翻译官**：把难记的 IP 地址（经纬度坐标）翻译成人好记的域名。来源：3.2
- **域名构成**：SLD（第二级，www 后自定义部分=品牌个性）+ TLD（顶级，.com 商业/.org 非营利/.net 网络服务；ccTLD 国家代码；newgTLD 如 .ai/.app 业务相关）。来源：3.2
- **域名 ≠ URL**：域名是主地址（google.com），URL 是详细地址（含协议+路径）。子域名=大房子的小房间（blog.example.com 划功能区/测试环境）。来源：3.2
- **专属域名价值**：建专业品牌形象、提升信任（免费子域名显不正式）、掌控在线身份、专业邮箱（info@yourbusiness.com）、间接助 SEO、防抢注、性价比营销。来源：3.2
- **选域名标准**：简短、易记、易拼、顺口。来源：3.2

## 3.3 Supabase——开源 BaaS
- **定位**：Firebase 的开源替代（后端即服务），基于 PostgreSQL。开源=透明（可查原理）/控制权（可改造）/自由度（可自托管搬迁，摆脱供应商锁定）。来源：3.3
- **数字总部比喻**：数据库=中央档案室、认证=门禁系统、API=内部通信网络。来源：3.3
- **四大模块**：①数据库（PostgreSQL，30 余年历史的金融级稳定系统）②认证 Auth（邮箱密码/魔法链接/Google/GitHub 一键登录）③实时 Realtime（WebSocket 推前端）④文件存储 Storage。来源：3.3
- **行级安全（RLS）**：核心安全特性，策略"用户只能查看操作 user_id 与自身认证 uid 匹配的记录"，即使绕过前端直接调 API 也阻止窥探他人数据。来源：3.3

## 一句话总结
节俭全栈 = Vercel（部署+CI/CD）+ 域名（数字身份）+ Supabase（开源 BaaS：数据库/认证/实时/存储），零成本起步、数据自主、安全下沉到数据库层。

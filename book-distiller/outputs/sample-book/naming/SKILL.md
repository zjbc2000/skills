# 代码命名规范

## 何时使用
- 用户说「帮我给这个变量 / 函数起名」。
- 用户问「这个命名好不好 / 怎么改进命名」。
- 代码评审中发现 a、b、tmp 这类名字，或命名靠注释才能看懂。

## 核心规则
1. **命名表达意图，注释兜底**：当需要写注释才能看懂变量时，先重命名而不是加注释。来源：第一章
2. **函数名以动词开头**：动作即名字，如 getUser、fetchData、calcTotal。来源：第二章
3. **布尔变量用 is/has 前缀**：如 isReady、hasChildren，让条件判断读起来像自然语言。来源：第二章
4. **避免无意义缩写**：缩写要能「读出来是什么」，无意义缩写破坏可读性。来源：第二章
5. **禁用占位名**：不要用 a、b、tmp 这类名字，用能描述用途的名字替换。来源：第三章
6. **缩写以「看得懂」为准**：缩写到没人看得懂等于没有命名，必要时写全称。来源：第三章

深入可加载 [第二章精要](../references/ch2-naming-rules.md) 与 [第三章精要](../references/ch3-common-mistakes.md)。

## 检查清单
- [ ] 每个函数名都以动词开头？
- [ ] 每个布尔变量都用了 is/has 前缀？
- [ ] 是否有仅靠注释才能解释的变量？（有则重命名）
- [ ] 是否残留 a、b、tmp 等占位名？
- [ ] 所有缩写是否都「读出来是什么」，无歧义？

# 子 Skill 模板

拆书产出的每个主题子 skill 按此模板生成。**全中文**（除 name 外的 frontmatter 值）。

## frontmatter

```yaml
---
name: "<kebab-case，小写，与目录名一致>"
description: "<全中文。写清 what（做什么）+ when（何时用）+ 触发关键词，至少一句。>"
---
```

## 正文结构（三明治 + 决策速查）

```markdown
# <主题名>

## 何时使用
- <触发场景，用户说什么时用这个 skill>

## 核心规则
- <从书中提取的可执行规则，每条标注 来源：第N章>

## 决策速查（v4.0）
- <作者在关键岔路口会怎么选，让人不重读全书就能照作者的判断行动>

## 检查清单
- [ ] <可勾选的检查项，供执行时自查>
```

## 决策速查怎么写（v4.0）

这是"推理辅助层"，不是术语表（术语归 references）也不是规则罗列（那是核心规则）。每行都要帮读者**做决定**。按优先级：

1. **决策规则**：`When X, do Y, because Z` —— 作者在关键场景的 if/then 判断。
2. **权衡矩阵**：竞争选项在作者关心的维度上打分，让读者按自己的约束挑选。
3. **阈值与默认值**：作者承诺的具体数字（"函数别超 ~20 行""错误预算 <10% 就告警"）。
4. **tells & smells**：快速识别信号（"看到 X，多半掉进 Y 坑"）。

禁止：裸术语→定义（那是 glossary）、散文段落（那是章节/精要）。紧凑、可打印在一页上。

## 规则

1. **不抄原文**：规则用自己的话提炼，保留出处标注（`来源：第N章`）防幻觉。
2. **密度优先**：宁要 5 条真规则，不要 20 条泛泛而谈。
3. **实践者视角**：写成"When X use Y"，不是教材式定义。
4. **决策速查聚焦"怎么选"**：每行是可执行的 if/then 或打分，不是概念解释。
5. 产出后用 `validate_skill.py` 校验每个 SKILL.md。

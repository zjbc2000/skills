# metric-packs: 行业指标包

> 用途：步骤 4「指标选型」的行业速查。每包给出：评分维度、量纲建议、证据校验方式、行业特定指标。复用通用 metrics（混淆矩阵/QWK/区分度/CI），包只决定"打什么分"。

## 包 1：简历筛选（worked example，见 worked-example.md）

- **评分维度**：通用（项目/技术栈/亮点）+ 特定（岗位匹配/技能命中）+ 红线一票否决。
- **量纲**：每条目 bonus 0-3（0=无,1=弱,2=中,3=强），每档配行为描述。
- **证据校验**：quotation 逐字引用 → 后置确定性 grep（exact/fuzzy/missing）——faithfulness 的确定性版。
- **行业特定指标**：引用准确率（exact/total）、逐指标区分度、阈值扫描（G 与 T 双闸门）。

## 包 2：客服质量（customer service）

- **评分维度**（各维度独立打分，别给一个总分）：
  - 意图识别正确（checklist 型，code-based 可覆盖）
  - 回答正确性（须引用内部知识库/KB 条目）
  - 语气与合规（不越权承诺、不含不当内容）
  - 目标达成（用户问题是否被解决，pass^K 语义——每次都要稳定）
- **量纲**：每条目 0-3 或 promptfoo `llm-rubric` 0-1 + threshold（模板 `templates/eval-contract.json`）。
- **证据校验**：KB 引用必须能在知识库原文找到（复用 quotation 校验逻辑）；无引用即 suspect。
- **行业特定指标**：意图混淆矩阵（意图 A 被判成 B 的集中度）、pass^K（同问题 3 次全过的比例）、kappa drift（judge 与人工一致性，阈值 0.55 告警——客服打分最容易因语气主观而 drift）。
- **数据**：真实对话 logs + 人工标注（解决/未解决二元 + 质量序数）。

## 包 3：内容审核（content moderation）

- **评分维度**：
  - 命中判定（违规类别：涉黄/涉暴/涉政/广告等——二元 hit，code-based 关键词可兜底）
  - 严重度分档（0-3：放行/警告/删除/上报）
  - 误杀率（合法内容被误判——**单侧 eval 的典型禁区**，must 测 shouldn't）
- **量纲**：类别命中用二元（配 Cohen's kappa）；严重度用序数（配 QWK）。
- **证据校验**：判定必须引用原文片段；`missing` 标记 suspect。
- **行业特定指标**：误杀率（FN 代价 >> FP）、每类别的 P/R（类别不平衡用 macro）、严重度档位的一致性矩阵（档位间混淆可视化）、跨模型一致性（多 judge 的 ICC）。
- **数据**：采样已审核内容 + 专家二重标注（审核领域二重标注是标配，kappa 报告直接决定合规可信度）。

## 选包流程（步骤 4 的执行细节）

1. 从本表挑最接近的行业包作底稿。
2. 圈定本系统的评分维度 → 每个维度写 0-3 档位的行为描述（锚定，非 vibe）。
3. 确认证据校验方式（引用/知识库/KB）。
4. 每维度独立打分（不给单一总分），聚合时加权 + 阈值。
5. 比例类指标全部配 Wilson/CI。

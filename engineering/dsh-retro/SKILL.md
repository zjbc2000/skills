# DSH 复盘

你（模型）读不出几个月的工作轨迹：原始会话日志以十亿 token 计。这条路是**先降维**——脚本把全部日志压成一份几万字符的摘要，你只读摘要，需要时再用 `--topic` 钻到单个话题。

## 1. 跑统计

```bash
python3 <skill-dir>/scripts/retro.py --days 7
```

默认对比上一个同等长度的周期。常用的变体：

| 目的 | 命令 |
|---|---|
| 一个月 | `--days 30` |
| 指定区间 | `--since 2026-10-01 --until 2026-10-15` |
| 追一个话题 | `--topic 合并冲突` |
| 留机读数据 | `--json /tmp/retro.json`（摘要仍打到 stdout） |
| 不要环比 | `--no-compare` |

完成标准：stdout 里出现 `## 概览`，且 `会话` 后面的数字大于 0。为 0 说明时间窗口里没有日志——把 `--days` 调大再跑。

摘要约 20 KB、240 行，覆盖：概览（会话/轮次/调用/token/缓存命中/环比）、项目分布、工具画像、Skill 使用、模型分布、模型错误最多的会话、产出物、域分布、摩擦信号、反复提及的词、会话清单、按日分布。

## 2. 读摘要，按四问切入

复盘的价值在「模式」而不在「清单」，逐条问：

1. **时间去哪了**——项目分布里哪几个仓吃掉了大头？和你以为的一致吗？
2. **重复在哪**——「反复提及的词」里哪些是同一件事换了说法？那件事该固化成 skill、脚本还是 AGENTS.md 一条规则？
3. **哪一步反复摩擦**——「摩擦信号」和「模型错误最多的会话」指向同一处时，那是结构性摩擦（工具不顺手、流程缺一步），不是偶发。
4. **产出了什么**——产出物扩展名分布对得上你的自我认知吗？.md 远多于 .ts 说明这周是文档周。

## 3. 需要证据时再钻

摘要只给计数。写复盘时若要引用具体某次对话的结论，用 `--topic <词>` 找出相关会话，再按需 `zstd -dc <session.v4.jsonl.zstd>` 打开那一个文件。一次一个文件，够用就停。

会话日志路径：`~/.dsh/sessions/<编码后的 cwd>/<session-id>/session.v4.jsonl.zstd`。

## 4. 产出复盘文档

按 `references/report-template.md` 的结构写。硬要求：

- 每个判断后面挂一个摘要里的数字（「前端占 6878 次命中」而不是「前端很多」）。
- 至少一条**下周要改的行为**，具体到可执行（「合并上游前先跑 check 基线」而不是「注意质量」）。
- 有环比就把环比一起写出来（「输入 +82%」比「输入 342M」有信息量）。

## 关键词维度（怎么给会话分组）

「反复提及的词」用两套信号：

- **预置词典**（`scripts/keywords.json`）——域（DSH/成本/前端/后端/工程操作/调研写作/抓取检索；**域要换成你自己的仓**）、活动（排查修复/重构优化/调研决策/实现开发/审查评审/同步运维/设计视觉）、摩擦点。命中计数直接告诉你这周偏哪一类工作。
- **自动发现**——中文 2-6 元 n-gram 与英文词，按「出现过该词的会话数」排序（不是出现次数，否则一段长粘贴会霸榜）。

要改分组口径就编辑 `keywords.json`：加一个维度 = 加一个 key，加一个值域 = 加一个子 key。维度设计原则见 `references/dimensions.md`。

## 边界

- 摘要里「反复提及的词」混着子代理回报和粘贴的原文，是**线索不是结论**——定论前先回摘要的会话清单核对。
- 脚本统计 `~/.dsh/sessions` 下全部工作区，不做项目过滤；只看某个仓就用 `--json` 输出后按 `project` 字段筛。

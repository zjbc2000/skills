# 复盘文档模板

标题：`<周期> 复盘`（例：`2026-10-18 ~ 10-24 复盘`）

```markdown
# <周期> 复盘

## 一句话
<这周最重要的一件事，以及它现在是完成还是卡着>

## 数字
| 指标 | 本周 | 上周期 | 变化 |
|---|---|---|---|
| 会话 / 调用 | | | |
| 未缓存输入 / 缓存读 | | | |
| 产出文件（主要扩展名） | | | |

## 四条线
### 时间去哪了
<项目分布 + 域分布，指出占比与意外>

### 重复劳动
<反复提及的词里哪些是同一件事；该固化成的载体（skill / 脚本 / AGENTS.md 规则 / 看板卡）>

### 摩擦点
<摩擦信号 + 模型错误最多的会话；区分「偶发」与「结构性问题」>

### 产出
<产出物扩展名分布说明了什么>

## 下周要改的
- [ ] <可执行的一条，带完成判据>
- [ ] <可执行的一条，带完成判据>

## 存疑
<摘要里无法自证、需要翻原始会话才能确认的点>
```

## 写法

**数字挂判断**。「前端相关命中 6878 次，占域分布的 27%，和上周期比没涨」有价值；「这周做了不少前端」没有。

**摩擦点要归因到机制**。「429 限流 26 次集中在 3 个会话」→ 那 3 个会话是不是都在跑长任务？如果是，改法是拆批次，不是「注意不要限流」。

**「下周要改的」只留你下周真的会做的**。三条以上说明在许愿，砍到两条。

**存疑区必须为空或写实话**。摘要只有计数，凡是要引用具体结论的地方都该指向原始会话；写不出就写「需要翻会话确认」，别编。

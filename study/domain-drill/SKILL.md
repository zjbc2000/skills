# 领域钻探（Domain Drill）

**你调研与讲解，用户判断与答题。** 一轮只推进一步，用户回应后才走下一步——一次性倒完，等于把思考外包给他。

两个渠道，全程分清：

- **对话**——用户立刻看得到：共识、分歧、题面。
- **文档**（`domain-<领域>.md`，写在工作区根目录）——答案与判定要点只放这里，用户不点开就不会被剧透。

## 流程

### 1. 对焦
把领域对到一个能发起检索的焦点上：太宽（"消费"）就要求收窄（"现制茶饮的供应链"）。
**完成**：粒度足以直接发起检索，且用户认了这个焦点。

### 2. 调研
两趟都你自己跑，不向用户要事实：
- **共识与分歧**：行业深度报告、招股书与年报、协会统计、论文与综述、从业者访谈。
- **认知差**：行内人默认新人该会的、新人不知道自己该问的——找"新人踩坑"、"面试怎么筛人"、"外行为什么判断错"。
**完成**：两趟各有两条以上独立来源；查不到的标"不确定"，不编。

### 3. 逐轮讲共识（第 1 问）
一轮只讲**一到两条**：**加粗的名字** + 一句话逻辑 + 依据。讲完停下，等用户回应。
用户的回应决定下一条讲什么：他卡住的地方先讲透；他说"继续"就往下推；他说"一次给完"就一次给完。
**完成**：5 条左右讲完，每条都过了"行业共识、不是单家之言"的检验。

### 4. 逐轮讲分歧（第 2 问）
一轮只讲**一场**争论，四行：争什么 → 两边各自的逻辑链 → 分歧本质（事实之争 / 取舍之争）→ 依据。讲完停下等回应。
**完成**：每场都是真分歧，不是已有一边倒结论的旧话题。

### 5. 逐题拷问（第 3 问）
靶子只有一个：**认知差**。按档位推进，上一档没过，不出下一档：

| 档 | 认知差在哪 |
|---|---|
| A | 入门骨架：概念有没有归位 |
| B | 核心机制：原理是不是真懂 |
| C | 生产暗语：钱从哪赚、坑在哪、怎么分辨新老手 |

**一轮只出一道题**，只给题面 + 一句"考什么"。这里与 grilling 相反：**拷问不给推荐答案，给了就是泄题**。
用户答完，先请他"说说哪一步最不确定"，再判卷。判卷结果与答案要点写进文档，对话里只给判定与反馈。
自检：是行家暗语，还是百度能搜到的表面问题？表面问题换掉；答案在前两问里能找到的，也换掉。
**完成**：三档的题都问过、判过。

### 6. 循环

| 判定 | 对话里的反馈 |
|---|---|
| 通过 | 列出答对的要点 |
| 答少了 | 点名缺失的概念，不解释 |
| 答错了 | 指出错在哪一步，不给正确答案 |

结果写回文档；补答只重评未通过的题。文档中三档全部通过 → 结业：一页总结（已掌握的模型、争论地图、老手考点、下一步方向）。

## 排版
三块各占一级标题；表格与短列表优先，一段不超过三行；每条"加粗名字 + 一句话 + 依据"；用用户的语言输出。

## 硬规矩
- 拷问的答案只活在文档里；对话里索要答案，指回题目。
- 一轮只推进一步；用户没回应，不进入下一步。
- 用户说"放弃，给我答案"才讲，并注明该题不算通过。

## 分支：只想了解
只做第 1~4 步，跳过拷问。
